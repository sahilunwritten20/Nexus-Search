# Phase 7 Plan — AI Search / RAG (docs only; no RAG code yet)

Scope: the engineering contract for Phase 7 BEFORE any implementation. Every
rule below is a design requirement derived from what Phases 1-6 actually
ship (not aspirations), in the WP0-WP11 style: root cause first, honest
limits stated, gates testable.

## 1. LLM API keys — env/secret store only

- The provider key arrives ONLY via environment / secret store
  (`NEXUS_LLM_API_KEY` from the same mechanism as `NEXUS_API_KEY`;
  Docker/K8s inject it — never a file in the repo, never a CLI arg, never
  a request parameter). `.env` is gitignored today and stays that way.
- NEVER logged: no logger call may format the key (partial or full); the
  failure path mirrors `core/api.py`'s storage-error stance — log the
  exception TYPE, never the payload. Add a test that boots the module with
  a poisoned key and asserts it appears in zero log records.
- NEVER exposed on `/metrics` or `/health`: both endpoints serialize
  config today (`/health` already reports only embedder NAME/dim — same
  discipline). New fields require a review against this rule. A test
  greps their JSON for the configured key value.
- Boot policy mirrors the existing fail-closed rule: production without a
  key does NOT start the RAG feature (degraded keyword/hybrid search
  keeps serving, `/health` reports the RAG subsystem as absent — the
  same degraded-boot pattern the vector store uses).

## 2. Retrieved text is UNTRUSTED — prompt-injection defenses

Everything the crawler ingested and every `/documents` write is
attacker-controlled content. Phase 7 treats retrieved chunks as DATA,
never as instructions:

- **Fence** every retrieved chunk in the prompt inside a delimiter frame
  the model is told to treat as quotable material only; the frame is
  generated by the RAG layer, not copied from document text (content
  cannot open/close its own frame).
- **Strip instruction-like content** from chunks before they enter the
  prompt: lines matching a small, tested pattern set ("ignore previous
  instructions", "system:", role markers, tool-invocation syntax) are
  redacted with the reason recorded in answer metadata. Stripping is
  additive metadata, never silent.
- **No tool access, no actions**: the Phase 7 answer path calls the LLM
  with tool-calling DISABLED; retrieved text can never trigger a fetch,
  a write, a tool, or a change of system prompt. There is no agent loop
  in Phase 7's scope — a decision that must be revisited (and re-audited)
  before any tool use exists.
- Injection tests are part of the suite from day one: a corpus seeded
  with injection payloads must produce answers that quote the payload as
  text, never obey it (regression floor, not best-effort).

## 3. Citation verification

- Every citation in an answer MUST reference a `doc_id`/`chunk_id`
  returned by retrieval for THIS request; the response layer re-checks
  each one against the retrieved set before the answer ships.
- Unverifiable citations: the citation is dropped and the answer is
  flagged (`citations_verified: false` + the failure reason in response
  metadata). An answer whose EVERY citation fails verification is refused
  outright — never shipped with invented sources.
- Chunk-level citations use the existing chunk metadata (`parent_id`,
  `chunk_id`, `chunk_index` — the same fields `search_page(group_chunks=)`
  produces), so a citation resolves to the exact stored row via the
  EXISTING `Storage.get_document` path.

## 4. Cost and abuse controls

- Per-key token caps: per-`X-API-Key` (and per-IP for the open path)
  rolling budgets on tokens sent to the provider, over a rolling window —
  same bucketing rule as `_rate_limit_key` (P0-3: only VERIFIED keys get
  key-buckets; everything else falls through to IP).
- Hard request timeout on every LLM call (default ≤ 30 s) + a bounded
  retry with jitter (≤ 2 retries, non-idempotent-capable calls fail
  fast instead).
- Concurrency limit on the LLM call: a small semaphore (default 4) —
  requests above it queue with a visible 429/Retry-After instead of
  dog-piling the provider. The `/search` rate limiter is reused as the
  first gate (it is per-IP today — the RAG endpoints add per-key caps on
  top, they do not relax it).
- Cost observability: tokens in/out and refusals counted per day in
  `/metrics` (already key-gated) — numbers only, never prompts or keys.

## 5. Streaming and conversation-context limits

- Streaming responses (SSE) only; the connection dies on the LLM timeout
  and the client gets a truncated-answer marker, never a silent hang.
- Conversation context: max turns per session (default 10), max total
  context tokens (default 4K), max bytes of retrieved text per turn —
  each enforced BEFORE the LLM call, each returning a clear 4xx.
- Per-session memory: the transcript lives in RAM only, capped (N turns
  × M tokens); no transcript is persisted to SQLite unless a future
  opt-in says so (PII stance matches the A/B log's retention story —
  `ranking.ab purge_older_than` is the precedent for scheduled removal).
- Session ids are client-supplied, treated as untrusted, and length-
  capped like every other request input.

## 6. Answer-quality benchmark (WP10 style)

Same protocol as `evaluation/semantic_benchmark/` (WP10), extended to
answers:

- Labeled fixture: questions + per-question ground-truth `doc_id` sets +
  expected answer facts, built with construction ground truth; committed
  60/40 dev/test split; results reported on held-out test only; paired
  bootstrap CIs; a coverage gate (refuses below 100% retrieval coverage).
- Categories mirror WP10 plus the two answer-specific ones:
  - **answerable** (cited answer whose facts match the fixture),
  - **partial** (some facts, must still cite only verified chunks),
  - **unanswerable** — MUST refuse ("no evidence in the corpus"), scored
    as a hard floor, because Phase 4's no-answer finding showed keyword
    mode serves confident junk (top-1 scores 5.4-9.1) while hybrid tops
    out at 0.03: the RAG layer must inherit hybrid's low-confidence
    behavior, not keyword's.
  - **injection** corpus (section 2's payloads must be quoted, never
    obeyed).
- Regression floors in default CI (hash-embedder-derived retrieval keeps
  the fixture deterministic); model-gated floors behind
  `NEXUS_RUN_MODEL_TESTS=1`. Floor failures fail CI — no silent quality
  regressions.

## 7. Where it plugs in

- Retrieval: the ONE shared `HybridSearch` instance the API already holds
  (`BUG-06` discipline — never a second instance per request); the RAG
  endpoints call `search_page(...)` with the same parameters/filters the
  `/search` endpoint uses. No new retrieval path, no second BM25, no
  shadow vector store.
- Data access: the existing shared `Storage`/SQLite connection set. A
  second SQLite connection path is FORBIDDEN — WAL single-writer
  semantics and the `data_version` reload contract only hold with one
  connection per store per process. If RAG needs new tables, they go
  through `core/migrations.py` like every other store.
- Chunking: reuse the ingestion chunk metadata (`parent_id` /
  `chunk_index` / `chunk_count`) for retrieval granularity and citations;
  no re-chunking at answer time.
- Surface: new endpoints (`/ask`, `/ask/stream`) follow the existing
  endpoint conventions — auth via `require_api_key`, read-gating via
  `_READ_AUTH` when enabled, rate limits via the shared limiter, models
  in `core/models.py` with bounded fields, errors that never leak
  internals.

---

Deferred to Phase 8+ (explicitly out of scope): distributed retrieval,
vector DB replacement, multi-model routing, tool use/agents, persistent
transcripts, click-feedback learning.
